# SUPERMONKEY 门店 / 教室

通过 `sm-c-cli boxes` 查询 SUPERMONKEY 附近门店（教室）。当前提供：

**Shortcut（按场景封装的高频入口）：**

- `+search-by-geo`：**根据经纬度**查询附近的门店，按距离正序返回。这是面向用户问题的最终入口。

**原子命令（流程中的辅助步骤，不直接服务用户提问）：**

- `boxes locations geocode`：把自然语言地理位置描述（如"海岸城"、"上海静安寺"）转换为**候选地址 + 经纬度**列表。当 agent 拿不到客户端经纬度、只能让用户口述位置时，先用它做地理编码，再把得到的经纬度交给 `+search-by-geo`。

## 调用流程（重要）

> **业务覆盖范围**：SUPERMONKEY 只在部分城市开展业务，完整白名单见 [`./references/cities.md`](./references/cities.md)。如果用户明确提到某个**不在白名单内**的城市（如"我在长沙"、"重庆有没有"），**直接告知"该城市暂无超级猩猩门店"，不要发起任何接口调用**。客户端经纬度无法直接判断城市，按正常流程调 `+search-by-geo`，由接口返回空列表兜底。

回答"附近有什么超级猩猩"这类问题时，遵循下面的决策路径：

1. **优先用客户端经纬度**。如果 agent 客户端 / 调用环境能直接拿到用户经纬度（飞书 / 企业微信 / 钉钉等 IM 客户端原生支持发送位置消息，发送后即可拿到），**直接用这对经纬度调用 `+search-by-geo`**，不要走地理编码这步。
2. **拿不到客户端经纬度时，先引导用户发送位置**。这是首选，比让用户口述位置更精确。
3. **用户拒绝发送位置 / 客户端不支持，再退回到口述位置**。让用户描述自己在哪儿（如"海岸城"、"上海静安寺"），用 `boxes locations geocode --keyword "<描述>"` 拿候选地址。然后：
   - **geocode 直接返回 0 条**：告诉用户"没找到匹配的位置，麻烦说得更具体一些（带上城市 / 区域）"，让用户重述，**不要**继续调 `+search-by-geo`。
   - **把候选里 `city` 不在业务覆盖白名单内的过滤掉**之后，按剩余数量处理：
     - **0 条**：告知用户"该城市暂无超级猩猩门店"，**不要**继续调 `+search-by-geo`。
     - **1 条**：直接拿候选的 `longitude` / `latitude` 调用 `+search-by-geo`，不必问用户确认。
     - **多条**：先在剩余候选里看是否有**明确匹配用户描述**的一条（如用户说"海岸城"，候选里恰好有 `address` / `district` 命中"海岸城"且其他候选只是同名/相近地点）。
       - **能锁定唯一明确匹配**：直接拿那条的 `longitude` / `latitude` 调用 `+search-by-geo`，不必问用户确认。
       - **没有明显胜出者**（多条都沾边、或都不太贴合用户原话）：把候选地址（`address` + `city` + `district`）列出来让用户选，例如「找到几个匹配的位置，请确认你说的是哪一个 …」。用户选定后再用对应候选的经纬度调 `+search-by-geo`。
4. **位置必须明确**。如果用户既没发送位置也没口述位置，**先按上面引导**，不要猜，也不要默认按某个城市查。

## Shortcut：+search-by-geo（查询附近门店）

```
sm-c-cli boxes +search-by-geo --longitude <经度> --latitude <纬度>
```

> 所有带空格 / 中文的参数值统一加双引号，避免 shell 把空格 / 中文截断。

参数：

- `--longitude` / `--latitude`（**均必填**）：经度 / 纬度。来源见上文「调用流程」。

### 使用示例

```
sm-c-cli boxes +search-by-geo --longitude "121.45" --latitude "31.22"
```

### 返回字段

stdout 是 `{ code, data, msg }` 信封；成功时 `data.list` 是按距离**正序**排列的门店数组。向用户呈现每家门店时，至少包含以下字段：

| 字段            | 含义                                                            |
| --------------- | --------------------------------------------------------------- |
| `boxName`       | 门店名称                                                        |
| `city` / `area` | 城市 / 区域                                                     |
| `address`       | 详细地址                                                        |
| `distance`      | 距离用户的距离，已带单位（如 `"900m"` / `"1.2km"`），可直接展示 |
| `addressGuide`  | 到店指引链接（图文路线说明），有需要时给用户                    |
| `type`          | 业态（当前固定 `class`，代表有团课的门店）                      |

另外两个字段 `boxId` 和 `boxIdSk` 是给后续接口使用的内部标识，**不要展示给用户**。

### 展示规则

- **结果已经按距离正序**。直接按返回顺序展示，不必重新排序。
- **`distance` 字段直接展示**。已经是 `"900m"` / `"1.2km"` 这种带单位的人类可读字符串，**不要**再做单位换算或数学加工。
- **按距离分层推荐，不要无差别铺一长串**：
  1. **优先推荐 3km 以内**的门店，前 3 ~ 5 家通常就够用。
  2. 如果接口返回的 `data.list` 直接就是空数组，直接对用户说类似的话语：「抱歉，附近没有查询到超级猩猩门店，建议你换个位置再试，或前往超级猩猩官方小程序查看完整门店列表」。

## 原子命令：locations geocode（地理编码）

```
sm-c-cli boxes locations geocode --keyword "<地理位置描述>"
```

参数：

- `--keyword`（必填）：用户口述的位置，原样传入；带空格 / 中文的描述务必加双引号。
  - 不要编造门牌号或路名，用户怎么说就怎么传，必要时只补全城市 / 区前缀。

### 使用示例

```
sm-c-cli boxes locations geocode --keyword "海岸城"
sm-c-cli boxes locations geocode --keyword "上海市静安区静安寺"
```

### 返回字段

stdout 是 `{ code, data, msg }` 信封；成功时 `data.list` 是候选地址数组（**可能为空 / 1 条 / 多条**），每条包含：

| 字段                     | 含义        |
| ------------------------ | ----------- |
| `address`                | 完整地址    |
| `country`                | 国家        |
| `province`               | 省份        |
| `city`                   | 城市        |
| `district`               | 区域        |
| `longitude` / `latitude` | 经度 / 纬度 |

> 这条命令的返回值不是直接给用户看的最终答案——它的产物（经纬度）是给 `+search-by-geo` 用的。具体怎么处理 0 / 1 / 多条候选，见上文「调用流程」第 3 步。

## 输出契约

stdout 统一是 `{ code, data, msg }` 信封：

- 成功：`code === 0`。
  - `+search-by-geo`：`data.list` 是按距离正序的门店数组（可能为空数组，表示该位置附近暂无门店，**不是错误**）。
  - `locations geocode`：`data.list` 是候选地址数组（可能为空 / 1 条 / 多条，**都不是错误**）。
- 失败：`code !== 0`，`msg` 是人类可读错误信息；同时 stderr 也会再写一份。

## 错误处理

- 信封里 `code !== 0` 即视为失败。把 `msg` 转述给用户，不要自行编造原因。
- 退出码非 0 时，先看 stdout 的信封 `msg`，再看 stderr 的补充信息。
- 参数错误（缺少 `--longitude` / `--latitude` / `--keyword` 等）会以 `code: 40001` 返回，`msg` 已经包含具体哪个 flag 出错，直接告诉用户即可。
- **出现错误时如实报告给用户，不要假想 / 猜测 / 编造门店数据或经纬度**。宁可告诉用户"查询失败"或"附近暂无门店"，也不要返回任何未经接口确认的门店信息或地址。
