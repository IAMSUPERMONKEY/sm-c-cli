# SUPERMONKEY 门店 / 教室

通过 `sm-c-cli boxes` 查询 SUPERMONKEY 门店（教室）。

## Shortcuts（推荐优先使用）

Shortcut 是按用户场景封装的高频入口（`sm-c-cli boxes +<verb> [flags]`）。有 Shortcut 的操作优先使用。

| Shortcut                                                 | 说明                                                                                                    |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| [+search-by-geo](./references/shortcut-search-by-geo.md) | **根据经纬度**查询附近门店，按距离正序返回。用户问"我附近 / 离我最近 / xx 地点附近有什么店"时用         |
| [+search](./references/shortcut-search.md)               | **按关键字**搜索门店（城市 / 区域 / 品类 / 门店名）。用户问"xx 区有什么店 / xx 店怎么去 / 地址在哪"时用 |

## 原子命令

原子命令与单个 OpenAPI 调用一一对应，是流程中的辅助步骤，不直接服务用户提问。

| 命令                                                                 | 说明                                                                              |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| [boxes locations geocode](./references/command-locations-geocode.md) | 把自然语言地理位置描述转换为**候选地址 + 经纬度**列表（拿不到客户端经纬度时使用） |

## 选哪个 shortcut

- **用户给的是位置信息**（"我在 xx" / 客户端位置 / "xx 附近 / 周围"）→ 走 `+search-by-geo`，按距离找最近的店。涉及经纬度 / 地理编码的多步编排，详见下文「附近门店查询流程」。
- **用户给的是文本关键字**（"xx 城市 / xx 区有什么店" / "xx 店地址 / 怎么去 / 在哪"）→ 直接走 `+search`，单次调用拿到门店列表与到店指引，没有额外流程。

无论用户是否点名"超级猩猩"，只要表达了健身 / 团课 / 运动需求，都按上面两类归入对应 shortcut。下面例句仅作意图归类参考，不是穷举：

- **走 `+search-by-geo`（位置维度，含未点名品牌）**：
  - "我附近 / 我周围有哪些超级猩猩 / 健身房 / 健身馆"
  - "离我最近的超级猩猩 / 健身房在哪"
  - "xx 地点附近有没有超级猩猩 / 能健身的地方 / 能上团课的"
  - "我想找个地方上健身课 / 团课，附近有吗"、"附近哪里能练 / 哪里能运动出汗"
- **走 `+search`（关键字维度，含未点名品牌）**：
  - "xx 城市 / xx 区有哪些超级猩猩 / 健身房"
  - "xx 区哪里能上团课 / 健身课"、"xx 商场附近有没有健身的地方"
  - "xx 门店在哪 / 地址 / 怎么去"

## 附近门店查询流程（仅适用于 `+search-by-geo`）

> 本节只覆盖**按位置找附近门店**的场景。按关键字找店请直接看 [`+search`](./references/shortcut-search.md)，无需走本流程。

> **业务覆盖范围**：SUPERMONKEY 只在部分城市开展业务，业务覆盖的城市范围见 [`./references/cities.md`](./references/cities.md)。如果用户明确提到某个**不在业务覆盖范围内的**的城市（如"我在长沙"、"重庆有没有"），**直接告知"该城市暂无超级猩猩门店"，不要发起任何接口调用**。客户端经纬度无法直接判断城市，按正常流程调 `+search-by-geo`，由接口返回空列表兜底。

回答"附近有什么超级猩猩"这类问题时，遵循下面的决策路径：

1. **优先用客户端经纬度**。如果 agent 客户端 / 调用环境能直接拿到用户经纬度（飞书 / 企业微信 / 钉钉等 IM 客户端原生支持发送位置消息，发送后即可拿到），**直接用这对经纬度调用 `+search-by-geo`**，不要走地理编码这步。
2. **拿不到客户端经纬度时，先引导用户发送位置**。这是首选，比让用户口述位置更精确。
3. **用户拒绝发送位置 / 客户端不支持，再退回到口述位置**。让用户描述自己在哪儿（如"海岸城"、"上海静安寺"），用 `boxes locations geocode --keyword "<描述>"` 拿候选地址。然后：
   - **geocode 直接返回 0 条**：告诉用户"没找到匹配的位置，麻烦说得更具体一些（带上城市 / 区域）"，让用户重述，**不要**继续调 `+search-by-geo`。
   - **把候选里 `city` 不在业务覆盖白名单内的过滤掉**之后，按剩余数量处理：
     - **0 条**：告知用户"该城市暂无超级猩猩门店"，**不要**继续调 `+search-by-geo`。
     - **1 条**：直接拿候选的 `longitude` / `latitude` 调用 `+search-by-geo`，不必问用户确认。
     - **多条**：先在剩余候选里看是否有**明确匹配用户描述**的一条（如用户说"海岸城"，候选里恰好有 `address` / `district` 命中"海岸城"且其他候选只是同名/相近地点）。
       - **能锁定唯一明确匹配**：直接拿那条的 `longitude` / `latitude` 调用 `+search-by-geo`，不必问用户确认。
       - **没有明显胜出者**（多条都沾边、或都不太贴合用户原话）：把候选地址（`address` + `city` + `district`）列出来让用户选，例如「找到几个匹配的位置，请确认你说的是哪一个 …」。用户选定后再用对应候选的经纬度调 `+search-by-geo`。
4. **位置必须明确**。如果用户既没发送位置也没口述位置，**先按上面引导**，不要猜，也不要默认按某个城市查。

## 输出契约

stdout 统一是 `{ code, data, msg }` 信封：

- 成功：`code === 0`。
  - `+search-by-geo`：`data.list` 是按距离正序的门店数组（可能为空数组，表示该位置附近暂无门店，**不是错误**）。
  - `locations geocode`：`data.list` 是候选地址数组（可能为空 / 1 条 / 多条，**都不是错误**）。
- 失败：`code !== 0`，`msg` 是人类可读错误信息；同时 stderr 也会再写一份。

## 错误处理

- 信封里 `code !== 0` 即视为失败。把 `msg` 转述给用户，不要自行编造原因。
- 退出码非 0 时，先看 stdout 的信封 `msg`，再看 stderr 的补充信息。
- 参数错误（缺少 `--longitude` / `--latitude` / `--keyword` 等）会以 `code: 40001` 返回，`msg` 已经包含具体哪个 flag 出错，直接告诉用户即可。
- **出现错误时如实报告给用户，不要假想 / 猜测 / 编造门店数据或经纬度**。宁可告诉用户"查询失败"或"附近暂无门店"，也不要返回任何未经接口确认的门店信息或地址。
