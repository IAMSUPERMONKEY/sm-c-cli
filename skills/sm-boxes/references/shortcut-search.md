# Shortcut：+search（按关键字搜索门店）

```
sm-c-cli boxes +search --keyword "<关键字>"
```

> 带空格 / 中文的参数值统一加双引号。

## 适用场景

这个 shortcut **不依赖经纬度**，按用户口述的文本关键字命中门店。两类典型问题都走它：

1. **按城市 / 区域 / 品类找店**：如「深圳福田区有什么店」「深圳的单车店」「上海有哪些门店」。关键字可以是城市、区、商圈、品类（如「单车」「肌力」），也可以组合（「深圳 单车」）。
2. **问"怎么去某门店"**：如「深圳海岸城店怎么去」「卓悦中心店在哪」。用门店名当关键字，返回的 `address`（详细地址）和 `addressGuide`（到店指引链接）就是答案。

> 与 `+search-by-geo` 的区别：`+search-by-geo` 是「我在 xx 附近，给我看最近的店」（要经纬度，按距离排序）；`+search` 是「按文本找店」（不要经纬度，不带距离）。

## 参数

- `--keyword`（必填）：关键字。用户怎么说就怎么传，必要时只补全城市前缀。

## 使用示例

```
sm-c-cli boxes +search --keyword "深圳 福田区"
sm-c-cli boxes +search --keyword "深圳 单车"
sm-c-cli boxes +search --keyword "海岸城"
```

## 返回字段

stdout 是 `{ code, data, msg }` 信封；成功时 `data.list` 是匹配的门店数组（**没有 distance 字段，结果未按距离排序**）。每条包含：

| 字段           | 含义                                                |
| -------------- | --------------------------------------------------- |
| `brandName`    | 品牌（如「超级猩猩」）                              |
| `boxName`      | 门店名称                                            |
| `city`         | 城市                                                |
| `district`     | 区域                                                |
| `address`      | 详细地址                                            |
| `addressGuide` | 到店指引链接（图文路线说明），用户问"怎么去"时给他 |

`boxId` / `boxIdSk` 是内部标识，**不要展示给用户**。

## 展示规则

- **结果为空数组**：告诉用户「没找到匹配的门店，换个关键字或更具体的描述试试」，不要编造。
- **「怎么去」场景**：把 `address`（详细地址）+ `addressGuide`（到店指引）一并给用户，不要只给其中一个。
- **「找店」场景**：列出 `boxName` + `city` / `district` + `address`；数量较多时按 `city` / `district` 分组呈现。
