# SUPERMONKEY 团课课程知识库

通过 `sm-c-cli class-courses +search` 按关键词检索超级猩猩团课课程的资料（课程简介、训练功效、适合人群、常见问题、注意事项）。

**核心用法：先查再答。** 当用户问到课程相关问题时，不要凭记忆回答，先用 `+search` 拿到课程资料作为上下文，再基于返回内容组织答复。本 skill 的产出是「回答用户问题的依据」，不是直接展示给用户的列表。回复用户时，不用表述你从课程知识库搜索到的资料内容，专注回答用户的相关问题。

## Shortcut：+search（搜索课程）

```
sm-c-cli class-courses +search --keyword "<关键词>"
```

> 关键词统一加双引号，避免 shell 把空格 / 中文截断。

参数：

- `--keyword`（必填）：课程检索关键词。从用户问题里**提炼出课程相关的核心词**，去掉「适合哪些人」「有什么」「怎么样」「是什么」「有哪些」之类的问句修饰。关键词可以是：
  - **课程名 / 课程缩写**：如 `莱美`、`BODYPUMP`、`BP`、`BC`、`战绳`、`搏击`。缩写直接当关键词传，不用展开。
  - **训练目标 / 功效 / 品类词**：如 `减肥`、`燃脂`、`塑形`、`力量`、`拉伸`。
  - **适合人群词**：如 `新手`、`孕妇`（当用户从人群角度发问时）。

### 如何从提问里提炼关键词

| 用户提问                  | 提炼出的关键词        | 说明                                      |
| ------------------------- | --------------------- | ----------------------------------------- |
| 「战绳课适合哪些人上？」  | `战绳`                | 取课程名核心词，丢掉「课 / 适合哪些人上」 |
| 「有哪些减肥课程」        | `减肥`                | 按训练目标 / 功效词检索                   |
| 「BODYPUMP 是练什么的？」 | `BODYPUMP`（或 `BP`） | 取课程名，问句部分丢弃                    |
| 「新手适合上什么课」      | `新手`                | 从适合人群角度检索                        |

- 提炼不出明确课程词、或用户问得很笼统（如「有什么好课推荐」）时，可以先用最贴近的目标 / 品类词试搜；仍然搜不到再让用户说得更具体一些，**不要编造课程**。

### 课程对比类问题（重要：要查多次）

当用户问「A 课和 B 课有什么区别 / 不同 / 哪个更适合我」这类**对比**问题时，**不要**把两个课程塞进同一个 `--keyword`，而是**对每个课程各查一次**，分别拿到资料后再综合对比作答。

例：「bp 和 bc 课有什么不同？」

```
sm-c-cli class-courses +search --keyword "bp"
sm-c-cli class-courses +search --keyword "bc"
```

拿到两次结果后，从 `classIntroduce` / `trainingEffect` / `suitablePeople` 等字段对比两节课的训练内容、功效、适合人群差异，再回答用户。

- 涉及 3 个及以上课程的对比，同理按课程逐个查询。
- 任一课程查不到（`list` 为空）时，如实告诉用户「没找到 xx 课的资料」，不要拿另一节课的内容硬凑或猜测。

### 使用示例

```
sm-c-cli class-courses +search --keyword "战绳"
sm-c-cli class-courses +search --keyword "减肥"
```

### 返回字段

stdout 是 `{ code, data, msg }` 信封；成功时 `data.list` 是课程数组，每条包含：

| 字段             | 含义     |
| ---------------- | -------- |
| `classId`        | 课程 ID  |
| `className`      | 课程名称 |
| `classIntroduce` | 课程简介 |
| `trainingEffect` | 训练功效 |
| `suitablePeople` | 适合人群 |
| `faq`            | 常见问题 |
| `note`           | 注意事项 |

回答用户时，按问题挑相关字段组织语言：问「适合谁」就讲 `suitablePeople`，问「练什么 / 有什么效果」就讲 `classIntroduce` / `trainingEffect`，问注意事项就讲 `note`。不要把整段原始 JSON 丢给用户。

## 输出契约

stdout 统一是 `{ code, data, msg }` 信封：

- 成功：`code === 0`，`data.list` 是课程数组。**`list` 为空数组表示没搜到匹配课程，不是错误**。
- 失败：`code !== 0`，`msg` 是人类可读错误信息；同时 stderr 也会再写一份。

## 错误处理

- 信封里 `code !== 0` 即视为失败。把 `msg` 转述给用户，不要自行编造原因。
- 参数错误（缺少 `--keyword`）会以 `code: 40001` 返回，`msg` 已包含具体出错的 flag，直接告诉用户即可。
- 退出码非 0 时，先看 stdout 的信封 `msg`，再看 stderr 的补充信息。
- **出现错误或搜到空结果时如实告知用户，不要假想 / 猜测 / 编造课程介绍、功效或适合人群**。宁可告诉用户「没找到这节课的资料」，也不要返回任何未经接口确认的课程信息。
